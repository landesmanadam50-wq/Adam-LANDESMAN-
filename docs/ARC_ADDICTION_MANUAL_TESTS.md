# ARC Addiction – בדיקות ידניות על מכשיר

**סטטוס: נכתב בלבד, לא בוצע על מכשיר.** הבדיקות האוטומטיות (`npm test`) מכסות לוגיקה וחיווט מקוד המקור.
הזרימה המלאה נבדקה גם בדפדפן (Expo web): פרופיל → ARC מסוגלות → טיימר → "לא" → עוצמה 0/4/5/10 → פעלתי → תיעוד → ARC קבלה → סיום → התקדמות.
הסעיפים שלמטה דורשים Android אמיתי: התראות, AlarmManager, Overlay, קוד Kotlin, הריגת אפליקציה.

## 1. פרופיל
- [ ] יצירת פרופיל: שם, תחושה, אזורי גוף במפה, "עלול לגרום נזק", זמן המתנה התחלתי (ברירת מחדל 1 דק').
- [ ] שמירה בלי שם מציגה שגיאה ולא נשמרת.
- [ ] עריכה: שינוי יעד, "להישאר באותו יעד", שינוי קצב לשני המדדים, מחיקת פרופיל (ההיסטוריה נשמרת).

## 2. ARC למסוגלות
- [ ] אזורי הדחף מהפרופיל מסומנים מראש במפת הגוף, ואפשר לשנות אותם.
- [ ] שלבי העיגול מתקדמים בהקשה אחת בלבד (אין דילוג כפול).
- [ ] "מה עזר לך בעבר" מציג תחושות תומכות מתרגולים קודמים של אותו פרופיל.
- [ ] תחושה תומכת שדורגה 6 ומעלה מופיעה בפרופיל תחת "תחושות תומכות שעזרו".
- [ ] אחרי שנשמר רגע הצלחה, שלב "רגע של מסוגלות" מופיע בתרגול הבא, ו"רגע הצלחה אחר" מחליף אותו.
- [ ] "דלג על התרגיל" עובר ישר לטיימר.

## 3. טיימר והתראה (אפליקציה פתוחה / ברקע / סגורה / נהרגה)
- [ ] בזמן ההמתנה מופיעה התראה קבועה שקטה עם ספירה לאחור, והיא נעלמת בסוף ההמתנה.
- [ ] יציאה מהאפליקציה: בסוף ההמתנה מגיעה התראה אמיתית "האם אתה בוחר לפעול לפי הדחף כרגע?" עם "כן" / "לא".
- [ ] אחרי הריגת האפליקציה (swipe away): ההתראה עדיין מגיעה בזמן.
- [ ] "לא" מההתראה: האפליקציה נפתחת על שאלת העוצמה.
- [ ] "כן" מההתראה: האפליקציה נפתחת על תיעוד ההתנהגות.
- [ ] לחיצה כפולה על הכפתור, או "לא" ואחריו "כן", לא משנה תשובה שכבר נרשמה.
- [ ] "סיום הטיימר" בהתראה הקבועה מעביר לשאלת הבחירה.
- [ ] פתיחת האפליקציה אחרי שההמתנה הסתיימה כשהיא סגורה מגיעה ישר לשאלת הבחירה.
- [ ] אין אף פעם שתי התראות סיום ושתי התראות קבועות במקביל, גם אחרי "עוד זמן המתנה" כמה פעמים.
- [ ] אתחול המכשיר באמצע המתנה: מתועד מה קורה (מגבלה ידועה של AlarmManager). פתיחת האפליקציה מסנכרנת מחדש.

## 4. עוצמת הדחף (ערכי גבול)
- [ ] 0: "סיום ותיעוד הצלחה" / "עוד זמן המתנה".
- [ ] 4: "המשך בפעילות הרגילה" / "עוד זמן המתנה" / "ARC נוסף".
- [ ] 5: "ARC נוסף למסוגלות" מוצע ראשון. אחריו חוזרים לטיימר.
- [ ] 10: אפשר גם "עוד זמן המתנה" או "סיום התרגול" (ה־ARC לא נכפה).
- [ ] אחרי 3 סבבים מופיעה ההודעה העדינה "אפשר גם לעצור כאן".

## 5. פעולה לפי הדחף וקבלה עצמית
- [ ] "פעלתי לפי הדחף" זמין בכל שלב לפני ההחלטה, גם באמצע ההמתנה, ומוביל לתיעוד ולקבלה עצמית.
- [ ] התנהגות שעלולה לגרום נזק: אין סטופר, יש רק תיעוד בדיעבד או "בלי לציין משך".
- [ ] התנהגות לא מזיקה: הסטופר נשמר גם אחרי יציאה וחזרה לאפליקציה.
- [ ] ARC קבלה עצמית מלא (13 שלבים): דירוג לפני, תגובות, נוכחות, גוף, מחשבה, שהייה, קבלה, הסבר, תחושה תומכת, ויסות, קידוד, כוונה, דירוג אחרי.
- [ ] אפשר לדלג על הקבלה העצמית. אין בשום מקום ניסוח של "כישלון" או של איפוס.

## 6. התקדמות
- [ ] עמידה ביעד → היעד הבא גדל בדקה (או לפי הקצב שנבחר).
- [ ] פעולה לפני סוף ההמתנה, או סיום מוקדם → היעד לא משתנה.
- [ ] משך התנהגות שתועד קובע יעד עדין. משך קצר ממנו, או שווה לו, מקטין את היעד בדקה, ומשך ארוך יותר לא משנה אותו.
- [ ] מסך ההתקדמות מציג את כל הגרפים, את ההיסטוריה ואת מספר בחירות ה"לא".
- [ ] "להקטין את היעד בדקה" ו"להישאר באותו יעד" עובדים.

## 7. Task LIVE והטיימר הצף
- [ ] במשימה פעילה, "🌱 דחף – ARC Addiction" פותח את המסלול. טיימר המשימה ממשיך לרוץ ולא נעצר.
- [ ] "חזרה למשימה (הטיימר ממשיך)" חוזר למשימה, והשורה מציגה את ספירת ההמתנה.
- [ ] בטיימר הצף מופיעה שורה שנייה "🌱 <שם> ⏳ mm:ss" במצב מכווץ ובמצב מורחב.
- [ ] השהיה, המשך, סיום או קיצור של המשימה לא משנים את השורה השנייה. סוף ההמתנה לא משנה את טיימר המשימה.
- [ ] סיום המשימה (הטיימר הצף נסגר): השורה השנייה חוזרת לבד, על פאנל idle.
- [ ] הקשה על השורה השנייה פותחת את מסך התרגול.
- [ ] בלי הרשאת overlay, או עם overlay כבוי בהגדרות: אין שורה שנייה, ואין שירות foreground ריק.
- [ ] כשההמתנה מסתיימת או נעצרת, השורה השנייה נעלמת.
